# Вход pprof_fix_4

Четвёртая задача правки уже опубликованных статей. Устроена она **точно так же**, как
`pprof_fix_2`: тот же вход, тот же поток `fetch → rewrite → update`, та же таблица, те же
команды. Своими у задачи остаются промпт правки и правило переименования заголовков; всё
остальное общее и живёт в `internal/pipeline/articlefix`.

Отдельная задача, а не второй промпт у соседа, потому что у неё своя пачка статей, своя схема
PostgreSQL и своя отметка «переписана»: общий список означал бы, что один прогон открывает
статьи другого.

Пачка четвёртая — страницы периодической аккредитации.

Переименование задано своё: `в ФИС ФРДО в Москве` → `сведений в ЕГИСЗ`.

**Текст статей задача пока не трогает вовсе** — меняются только заголовки (название записи,
`prof_title`, `_yoast_wpseo_title`), а к модели прогон не ходит. Промпт правки лежит
черновиком (копия `pprof_fix_2`) и ждёт своего регламента; когда он будет написан, снимите
`TextUnchanged: true` в `internal/tasks/pproffix4/profile.go`.

## Что положить в этот каталог

Ровно один файл: в каждой строке индекс и ссылка на статью. Форматы — `.xlsx`, HTML-таблица,
CSV, просто список строк; шапка не нужна. Подробности разбора — в `input/pprof_fix_1/README.md`,
правило разбора у задач общее.

Явный путь к файлу — `PPROF_FIX_4_INPUT_FILE_PATH`.

## Чем отличается от pprof_fix_2

| | `pprof_fix_2` | `pprof_fix_4` |
|---|---|---|
| Пачка | переподготовка врачей | периодическая аккредитация |
| Переименование | «дистанционная переподготовка» → «профессиональная переподготовка» | «в ФИС ФРДО в Москве» → «сведений в ЕГИСЗ» |
| Правка текста | таблица заработка и форма записи часов обучения | пока никакой: текст не меняется, модель не спрашивается |
| Схема PostgreSQL | `pprof_fix_2` | `pprof_fix_4` |
| Префикс переменных | `PPROF_FIX_2_` | `PPROF_FIX_4_` |

## Что править перед прогоном

| Файл | Что задаёт |
|---|---|
| `tasks/pprof_fix_4/prompts/rewrite.txt` | сама правка |
| `tasks/pprof_fix_4/title_rule.txt` | пара «было — стало» для заголовков |

Промпт пока унаследован от `pprof_fix_2` и **в модель не уходит**: задача меняет только
заголовок. Когда до текста дойдёт дело, снимите `TextUnchanged` в профиле. Черновик просит
две вещи: переделать таблицу блока «Уровни квалификации, должности и заработок» (должность, зарплата, обязанности; зарплата двумя строками, обязанности через
`<br>` без маркеров, ширины 18/24/58, источник hh.ru) и привести все упоминания часов
обучения к приблизительной форме — «от 250 акад. ч» или «250+ академических часов», не меняя
самого числа.

## Команды

```bash
make pprof-fix-4 import             # прочитать файл из этого каталога
make pprof-fix-4 wordpress-check    # доступ к площадке, без записи
make pprof-fix-4 run plan           # что изменится, без единой правки
make pprof-fix-4 run 12             # правка одной статьи и запись в блог
make pprof-fix-4 run                # все непереписанные статьи
make pprof-fix-4 reset              # задача к нулю: пустая таблица и пустые артефакты
```

Первый запуск задачи требует своей схемы PostgreSQL — она создаётся руками, как у всех
задач:

```bash
docker exec -i seo-postgres psql -U seo -d seo -c 'CREATE SCHEMA IF NOT EXISTS pprof_fix_4'
docker exec -i seo-postgres psql -U seo -d seo -v ON_ERROR_STOP=1 \
  -c 'SET search_path TO pprof_fix_4' -f - < migrations/pprof_fix_4/000001_schema.up.sql
```

И своих переменных площадки: `PPROF_FIX_4_WORDPRESS_URL`, `PPROF_FIX_4_WORDPRESS_USERNAME`,
`PPROF_FIX_4_WORDPRESS_APP_PASSWORD`.

## О чём помнить

Всё то же, что у первой задачи, и по тем же причинам: правка необратима, прежний текст
остаётся только в `original/`, `reset` его удаляет, переписанную статью повторный `run`
пропускает, упавшая статья не роняет пачку. Разбор — в `input/pprof_fix_1/README.md` и в
корневом `README.md`.
