# Входные данные pprof_2

Сюда кладётся ровно одна книга Excel — имя любое, значимо только расширение `.xlsx`.
Файл выбирает `importer.ResolveWorkbook`: пустой каталог и две книги одинаково остановят
импорт с вопросом к человеку. Явный путь задаётся переменной `PPROF_2_INPUT_FILE_PATH` и
выигрывает всегда.

## Колонки книги

Заголовки читаются без учёта регистра и пробелов по краям. Порядок колонок значения не имеет,
лишние колонки игнорируются.

| Заголовок в Excel  | Поле               | Обязательна | Куда идёт                                       |
|--------------------|--------------------|-------------|-------------------------------------------------|
| `id`               | `external_id`      | да          | идентификатор статьи во всех командах CLI       |
| `article_name`     | заголовок статьи   | да          | «Название» в `result.md`, заголовок записи блога|
| `service_name`     | `service_name`     | нет         | «Название услуги» — сама услуга, без уточнений  |
| `slug`             | `image_slug`       | да          | имя каталога артефактов и «URL картинки»        |
| `reference_url`    | `reference_url`    | да          | вход Keys.so на этапе `prepare`                 |
| `header`           | `header`           | нет         | «Заголовок (H1)» и «Alt главной картинки»       |
| `seo_title`        | `seo_title`        | нет         | «SEO-заголовок»                                 |
| `meta_description` | `meta_description` | нет         | «Мета-описание»                                 |
| `key_word`         | `key_word`         | нет         | «Фокусное ключевое слово»                       |
| `category`         | `category`         | нет         | «Категория»                                     |
| `section`          | `section`          | нет         | «Рубрика» — уровень каталога крупнее категории  |
| `profession`       | `profession`       | нет         | «Название профессии»                            |
| `teachers`         | `teachers`         | нет         | «Преподаватели»                                 |

Обязательные колонки проверяет импортёр, а не схема PostgreSQL: он умеет назвать номер строки
и колонку, а constraint — нет. Строка без `id`, `article_name`, `slug` или `reference_url`
попадает в отчёт импорта с причиной и не импортируется.

Колонки `author` в схеме нет: у страницы услуги автора не бывает, преподаватели живут в своём
поле, и хранить одно значение дважды незачем.

`article_name` и `service_name` — разные значения, а не синонимы: первое полное («Медицинский
массаж — дистанционное обучение с практикой и внесением в ФИС ФРДО») и становится заголовком
статьи, второе короткое («Медицинский массаж») и живёт своей колонкой. Вывести одно из
другого нельзя: уточнения в полном названии пишет человек.

Часть заголовков книга называет иначе, чем движок: `slug` — это `image_slug`, а `teachers` —
та же колонка книги, что `authors` у остальных задач. Синонимы (`услуга-нейм` и `услуга_нейм` для `service_name`, `сео-заголовок`,
`преподаватели`, `профессия`, `image_slug`, `authors`) разбирает таблица `columnAliases`
в `internal/pipeline/importer/excel.go`; двух имён одной колонки в книге быть не должно —
импорт остановится на «повторяющийся заголовок».

Колонок `tags`, `professions` и `links` в книге нет, и это не упущение: меток `pprof_2` в
блог не публикует, списка похожих профессий в `result.md` не печатает, а перелинковки у него
нет вовсе — промпт стадии `html` запрещает любые ссылки, внутренние и внешние. В схеме
PostgreSQL этих колонок тоже нет: набор колонок задачи описан её собственной миграцией
`migrations/pprof_2/`. Понадобятся — придётся вернуть и колонку, и строку в
`Profile.ExtraInputColumns`, и работу с ней в промпте.

## Что ещё лежит в каталоге

- `images/` — обложки статей, по одной на `external_id`;
- `regulations/html/` — регламент вёрстки, уходит документом в чат 3 стадии `html`.

Книга, картинки и регламент в git не попадают, в репозитории остаются только эти пояснения.
