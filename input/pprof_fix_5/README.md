# Вход pprof_fix_5

Пятая задача правки уже опубликованных статей. Устроена она **точно так же**, как
`pprof_fix_2`: тот же вход, тот же поток `fetch → rewrite → update`, та же таблица, те же
команды. Своё у неё одно — что именно правится: страница переводится на **НМО**, непрерывное
медицинское образование. И **заголовок записи она не трогает**.

Ни название записи (`post_title`), ни видимый H1 страницы (`prof_title`), ни SEO-заголовок
(`_yoast_wpseo_title`) не меняются. Файла `title_rule.txt` у задачи поэтому нет вовсе: пустой
путь к правилу в профиле и означает «заголовок оставить как есть» — так же устроен
`pprof_fix_3`. Меняется только текст статьи, и что именно — говорит
`tasks/pprof_fix_5/prompts/rewrite.txt`.

Отдельная задача, а не ещё один промпт у соседей, потому что у неё своя пачка статей, своя
схема PostgreSQL и своя отметка «переписана»: общий список означал бы, что один прогон
открывает статьи другого.

## Что делает правка

Услуга из профессиональной переподготовки становится повышением квалификации в рамках НМО:

- лид, три плашки и финальный блок — про НМО, удостоверение о повышении квалификации и
  передачу сведений в ФИС ФРДО; диплома о переподготовке в статье не остаётся;
- добавляются оговорки: НМО не присваивает новую специальность, не заменяет профессиональную
  переподготовку и аккредитацию, дохода и категории не гарантирует;
- умения выпускника формулируются как актуализация уже имеющихся компетенций;
- таблица заработка переделывается в три столбца — уровень, зарплата, типовые обязанности
  (ширины 32/20/48) — с источником hh.ru после неё;
- заголовки разделов теряют «переподготовку»; последний становится «Пройдите НМО по … и
  актуализируйте профессиональные компетенции».

Число академических часов промпт менять запрещает: оно берётся из самой статьи. Врачебная
фактура, модули, имена преподавателя и авторов отзывов остаются прежними.

Раз заголовки разделов переписываются, обрыв ответа ловится структурой, а не дословной
сверкой последнего заголовка — за это отвечает `ArticleFix.HeadingsRewritten` в профиле.

## Что положить в этот каталог

Ровно один файл: в каждой строке индекс и ссылка на статью. Форматы — `.xlsx`, HTML-таблица,
CSV, просто список строк; шапка не нужна. Подробности разбора — в `input/pprof_fix_1/README.md`,
правило разбора у задач общее.

Явный путь к файлу — `PPROF_FIX_5_INPUT_FILE_PATH`.

## Порядок запуска

```text
make pprof-fix-5 import         прочитать этот каталог
make pprof-fix-5 run plan       что найдено в блоге — читает статьи, ничего не пишет
make pprof-fix-5 run [ID]       правка и запись в блог; без ID — все непереписанные
make pprof-fix-5 reset          задача к нулю: пустая таблица и пустые артефакты
```

Первый запуск требует своей схемы PostgreSQL — она создаётся руками, как у всех задач:

```bash
docker exec -i seo-postgres psql -U seo -d seo -c 'CREATE SCHEMA IF NOT EXISTS pprof_fix_5'
docker exec -i seo-postgres psql -U seo -d seo -v ON_ERROR_STOP=1 \
  -c 'SET search_path TO pprof_fix_5' -f - < migrations/pprof_fix_5/000001_schema.up.sql
```

И своих переменных площадки: `PPROF_FIX_5_WORDPRESS_URL`, `PPROF_FIX_5_WORDPRESS_USERNAME`,
`PPROF_FIX_5_WORDPRESS_APP_PASSWORD`.

## О чём помнить

Всё то же, что у соседей, и по тем же причинам: правка необратима, прежний текст остаётся
только в `original/`, `reset` его удаляет, переписанную статью повторный `run` пропускает,
упавшая статья не роняет пачку. Разбор — в `input/pprof_fix_1/README.md` и в корневом
`README.md`.
