# Вход pprof_fix_3

Третья задача правки уже опубликованных статей. Устроена она **точно так же**, как
`pprof_fix_1` и `pprof_fix_2`: тот же вход, тот же поток `fetch → rewrite → update`, та же
таблица, те же команды. Отличие ровно одно и оно содержательное — **заголовок она не
трогает**.

Ни название записи (`post_title`), ни видимый H1 страницы (`prof_title`), ни SEO-заголовок
(`_yoast_wpseo_title`) не меняются. Файла `title_rule.txt` у задачи поэтому нет вовсе: пустой
путь к правилу в профиле и означает «заголовок оставить как есть». Меняется только текст
статьи, и что именно — говорит `tasks/pprof_fix_3/prompts/rewrite.txt`.

Отдельная задача, а не третий промпт у соседей, потому что у неё своя пачка статей, своя схема
PostgreSQL и своя отметка «переписана»: общий список означал бы, что один прогон открывает
статьи другого.

## Что положить в этот каталог

Ровно один файл: в каждой строке индекс и ссылка на статью. Форматы — `.xlsx`, HTML-таблица,
CSV, просто список строк; шапка не нужна. Подробности разбора — в `input/pprof_fix_1/README.md`,
правило разбора у задач общее.

Явный путь к файлу — `PPROF_FIX_3_INPUT_FILE_PATH`.

## Порядок запуска

```text
make pprof-fix-3 import         прочитать этот каталог
make pprof-fix-3 run plan       что найдено в блоге — читает статьи, ничего не пишет
make pprof-fix-3 run [ID]       правка и запись в блог; без ID — все непереписанные
```

`run` не начнётся, пока в `tasks/pprof_fix_3/prompts/rewrite.txt` стоит метка
`<!-- ЗАПОЛНИТЬ -->`: правку живых статей откатить нечем. `run plan` работает и до неё —
он затем и нужен, чтобы проверить пачку, пока регламент правок пишется.
