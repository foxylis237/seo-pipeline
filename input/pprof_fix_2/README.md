# Вход pprof_fix_2

Вторая задача правки уже опубликованных статей. Устроена она **точно так же**, как
`pprof_fix_1`: тот же вход, тот же поток `fetch → rewrite → update`, та же таблица, те же
команды. Отличий ровно два — промпт правки и правило переименования заголовков; всё
остальное общее и живёт в `internal/pipeline/articlefix`.

Отдельная задача, а не второй промпт у первой, потому что у неё своя пачка статей, своя схема
PostgreSQL и своя отметка «переписана»: общий список означал бы, что один прогон открывает
статьи другого.

Пачка вторая — страницы переподготовки врачей.

## Что положить в этот каталог

Ровно один файл: в каждой строке индекс и ссылка на статью. Форматы — `.xlsx`, HTML-таблица,
CSV, просто список строк; шапка не нужна. Подробности разбора — в `input/pprof_fix_1/README.md`,
правило разбора у задач общее.

Явный путь к файлу — `PPROF_FIX_2_INPUT_FILE_PATH`.

## Чем отличается от pprof_fix_1

| | `pprof_fix_1` | `pprof_fix_2` |
|---|---|---|
| Пачка | обучение медсестёр | переподготовка врачей |
| Переименование | «… с внесением в ФИС ФРДО» → «… с практикой и внесением в ФИС ФРДО» | «дистанционная переподготовка» → «профессиональная переподготовка» |
| Правка текста | услуга подаётся как обучение, а не повышение квалификации; плашки, таблица заработка, документ | таблица заработка и форма записи часов обучения |
| Схема PostgreSQL | `pprof_fix_1` | `pprof_fix_2` |
| Префикс переменных | `PPROF_FIX_1_` | `PPROF_FIX_2_` |

## Что править перед прогоном

| Файл | Что задаёт |
|---|---|
| `tasks/pprof_fix_2/prompts/rewrite.txt` | сама правка |
| `tasks/pprof_fix_2/title_rule.txt` | пара «было — стало» для заголовков |

Промпт этой задачи просит две вещи: переделать таблицу блока «Уровни квалификации, должности
и заработок» (должность, зарплата, обязанности; зарплата двумя строками, обязанности через
`<br>` без маркеров, ширины 18/24/58, источник hh.ru) и привести все упоминания часов
обучения к приблизительной форме — «от 250 акад. ч» или «250+ академических часов», не меняя
самого числа.

## Команды

```bash
make pprof-fix-2 import             # прочитать файл из этого каталога
make pprof-fix-2 wordpress-check    # доступ к площадке, без записи
make pprof-fix-2 run plan           # что изменится, без единой правки
make pprof-fix-2 run 12             # правка одной статьи и запись в блог
make pprof-fix-2 run                # все непереписанные статьи
make pprof-fix-2 reset              # задача к нулю: пустая таблица и пустые артефакты
```

Первый запуск задачи требует своей схемы PostgreSQL — она создаётся руками, как у всех
задач:

```bash
docker exec -i seo-postgres psql -U seo -d seo -c 'CREATE SCHEMA IF NOT EXISTS pprof_fix_2'
docker exec -i seo-postgres psql -U seo -d seo -v ON_ERROR_STOP=1 \
  -c 'SET search_path TO pprof_fix_2' -f - < migrations/pprof_fix_2/000001_schema.up.sql
```

И своих переменных площадки: `PPROF_FIX_2_WORDPRESS_URL`, `PPROF_FIX_2_WORDPRESS_USERNAME`,
`PPROF_FIX_2_WORDPRESS_APP_PASSWORD`.

## О чём помнить

Всё то же, что у первой задачи, и по тем же причинам: правка необратима, прежний текст
остаётся только в `original/`, `reset` его удаляет, переписанную статью повторный `run`
пропускает, упавшая статья не роняет пачку. Разбор — в `input/pprof_fix_1/README.md` и в
корневом `README.md`.
