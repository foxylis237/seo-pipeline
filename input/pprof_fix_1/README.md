# Вход pprof_fix_1

Задача не пишет статьи, а **правит уже опубликованные**: находит запись в блоге, отдаёт её
текст модели с регламентом правки, возвращает исправленный HTML в ту же запись и попутно
переименовывает заголовки. Пачка первая — страницы обучения медсестёр
(«… с внесением в ФИС ФРДО» → «… с практикой и внесением в ФИС ФРДО»).

Общее устройство обеих задач правки — в корневом `README.md`, раздел «Задачи правки
опубликованных статей». Здесь только то, что нужно, чтобы запустить эту.

## Что положить в этот каталог

Ровно один файл. Имя любое, важно содержимое: в каждой строке **индекс и ссылка на статью**.

Читается что угодно из этого:

| Формат | Как выглядит строка |
|---|---|
| `.xlsx` | две колонки: `1` и `https://dpoprof.ru/obuchenie-medpersonala/medsestra-v-shkole/` |
| HTML | `<tr><td>1</td><td><a href="https://…">Медсестра в школе</a></td></tr>` |
| CSV | `1,https://…` |
| текст | `1 https://…` |

Шапка не нужна, порядок строк не важен, лишние колонки игнорируются. В книге Excel ссылка
может быть спрятана под текстом ячейки — адрес гиперссылки берётся тоже.

Правило одно: **первое число до первой ссылки** в строке. Ссылка без индекса или повторный
индекс останавливают импорт с номером строки — молча пропустить статью нельзя, её отсутствие
обнаружится только по блогу и через недели.

Индекс — это `external_id`: им статья называется в командах и в имени каталога артефактов.
Слаг для поиска записи берётся из адреса, отдельной колонкой его писать не нужно.

Явный путь к файлу вместо поиска по каталогу — `PPROF_FIX_1_INPUT_FILE_PATH`.

## Что править перед прогоном

| Файл | Что задаёт |
|---|---|
| `tasks/pprof_fix_1/prompts/rewrite.txt` | сама правка: что менять в статье. Ниже правок — формат ответа, его трогать не нужно |
| `tasks/pprof_fix_1/title_rule.txt` | пара «было — стало», из которой выводится переименование заголовков |

Заголовок модель не пишет: из пары «было — стало» код сам выводит, что изменилось, и
применяет ту же правку к каждой статье. Меняются три заголовка сразу — название записи,
поле темы `prof_title` (это H1 на самой странице) и SEO-заголовок Yoast, если правило к нему
подходит. Статья, к заголовку которой правило не подошло, останавливается **до** запроса к
модели: за неподходящую правку не платим.

## Команды

```bash
make pprof-fix-1 import             # прочитать файл из этого каталога
make pprof-fix-1 import 5           # только первые пять строк
make pprof-fix-1 wordpress-check    # доступ к площадке, без записи
make pprof-fix-1 run plan           # что изменится во всех статьях, без единой правки
make pprof-fix-1 run plan 12        # то же по одной статье
make pprof-fix-1 run 12             # правка одной статьи и запись в блог
make pprof-fix-1 run                # все непереписанные статьи
make pprof-fix-1 reset              # задача к нулю: пустая таблица и пустые артефакты
```

Порядок первого запуска: `import` → `run plan` → `run <id>` на одной статье → `run` на всех.
План читает блог и ничего не меняет — по нему видно, правильно ли сработает переименование.

Других операций у задачи нет: `prepare`, `publish`, `regenerate` и прочие отбиваются на
старте с объяснением.

## Что остаётся после прогона

```text
tasks/pprof_fix_1/output/<индекс>-<слаг>/
  original/article.html    статья до правки — единственная копия прежнего текста
  original/title.txt       заголовок до правки
  prompts/rewrite_prompt.txt  что именно ушло в модель
  generated/article.html   статья после правки, она же лежит в блоге
  result.md                название и ссылка
```

## О чём помнить

- **Правка необратима.** Команды, возвращающей прежний текст в блог, нет. Старая версия
  остаётся только в `original/` — и её удалит `reset`.
- **Повтор защищён отметкой.** Переписанную статью `run` пропускает: иначе модель получила бы
  на вход собственный вывод.
- **Упавшая статья не роняет пачку.** Причина ложится в `articles.error_message`, прогон идёт
  дальше, следующий `run` подхватит упавшие. Посмотреть:
  `SELECT external_id, error_message FROM pprof_fix_1.articles WHERE status = 'failed';`
- **Оборванный ответ модели дописывается** продолжением того же чата, до двух раз. Не
  сошлось — статья падает, и в блог не уходит ничего.
- **Переменные площадки свои:** `PPROF_FIX_1_WORDPRESS_URL`, `PPROF_FIX_1_WORDPRESS_USERNAME`,
  `PPROF_FIX_1_WORDPRESS_APP_PASSWORD`. Значения те же, что у `pprof_2` — блог один, но
  переменная без префикса в задачу не протекает.
