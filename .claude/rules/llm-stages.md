# LLM-стадии и маршрутизация

## Единый источник истины для маршрутизации

`LLMStageConfig` хранит и legacy-поля `Provider`/`Model`, и новые `Targets`. Синхронизирует их
одна строка в `validateLLMConfig`. Из-за этого dry-run сломан: он пишет в `stage.Model`,
а `Router.generateTarget` читает `target.Model`.

**Правило: маршрутизация читается и пишется только через `stage.Targets`.** Legacy-поля
не использовать в новом коде; YAML-совместимость схлопывать в `Targets` при валидации.

Логировать фактический `result.Model` после ответа, а не `Targets[0]` до запроса — иначе при
срабатывании fallback лог врёт.

## Добавление провайдера

Провайдер обязан реализовать `llm.Client` (`Generate`). Всё остальное — `Close()`, `NewChat` —
опционально. Конструирование сейчас в `switch` внутри `main()`; при добавлении третьего
провайдера выносить в реестр `map[string]constructor`, а не расширять `switch` (см.
`.claude/rules/architecture.md`, раздел OCP).

## Добавление стадии

Обязательные стадии перечислены в `requiredLLMStages` (`internal/config/llm.go`).
Стадия существует, только если она есть во всех местах сразу — используйте `/stage-add`,
чтобы не пропустить ни одно.

## Контракт ответа

Каждая стадия проверяет непустой ответ **до** сохранения. `StructureService` этого не делает —
единственная стадия без проверки; при добавлении новой не копировать этот образец.

Маркер `[[ARTICLE_COMPLETE]]` вырезается из `article` и `fix` перед записью.
HTML проходит `normalizeAndValidateHTML` — снятие Markdown-обёртки и проверка на наличие
заголовка или абзаца.

## Таймауты и повторы

`stage.Timeout` из YAML сейчас применяется **к каждому target отдельно**, поэтому два target'а
на стадии `fix` (300s) дают до 10 минут. Трактовать таймаут как бюджет на всю стадию,
включая fallback.

Повтор — до 3 попыток, только для временных ошибок (`isTemporary` по типам). Fallback на
следующий target — только при quota/rate-limit/502/503/504/deadline (`isFallbackEligible`).

## Промпты

Промпты — Go-шаблоны `text/template`, поля приходят из структуры в `llm.Call{Data: ...}`.
Список полей шаблона и полей структуры должен совпадать: несовпадение даёт `<no value>`
в проде, а не ошибку. Правка промпта — через `/prompt-tune`.

`stageChat` эмулирует диалог склейкой всей истории в один текстовый транскрипт, потому что
провайдеры stateless. У Gemini и OpenAI-совместимого есть нативный чат (`NewChat`), но он
сейчас мёртвый код.

## Секреты

Сообщения провайдера проходят `safeProviderMessage` перед логированием. Ключи в логи,
ошибки и артефакты не попадают.
