# Production Go

## Ошибки

- Оборачивать с контекстом действия: `fmt.Errorf("сохранить путь HTML: %w", err)`.
- Классифицировать через `errors.As` по типам — `llm.StatusError`, `keysso.StageError`,
  `arsenkin.StageError`, `generation.StageError`. **Не** через `strings.Contains` по тексту
  сообщения: `classifyErrorOperation` и `isRetryableError` так и написаны. Имена операций
  уже провайдеро-нейтральны (`llm_*`), но сама классификация по подстрокам остаётся хрупкой:
  меняется текст ошибки — молча меняется операция.
- `net.Error.Temporary()` устарел с Go 1.18 — линтер это отмечает в трёх местах.
  Замена: `netErr.Timeout()` плюс явные `errors.Is(err, syscall.ECONNRESET/ECONNREFUSED)`.
- Одна политика повторов на проект. Сейчас их две: `llm.isTemporary` (по типам, правильная)
  и `repository.isRetryableError` (по 17 подстрокам). Расходятся.

## Контекст

- `ctx` — первый параметр, никогда не в структуре.
- Не подменять живой `ctx` на `context.Background()`. Линтер даёт 30 срабатываний
  `contextcheck`, в основном в `keysso.log` и `arsenkin.log`.
- Таймаут задаётся на своём уровне ровно один раз. Сейчас они вложены: `pipeline` ставит
  `articleCall.Timeout`, `Router.generateTarget` поверх ставит `stage.Timeout` на **каждый**
  target, а `gemini` добавляет свой хардкод в 5 минут. Итог — до 10 минут на одну стадию.

## Конкурентность

- `stopHeartbeat()` и подобные завершатели — через `defer`, иначе паника в клиенте оставляет
  goroutine жить (`llm.go`, `generateTarget`).
- Функция-завершатель должна быть идемпотентной (`sync.Once`): повторный `close` канала — паника.
- Persistent-профиль браузера защищается `flock`. У Arsenkin и DeepSeek это есть, у Keys.so нет.

## Конструкторы и интерфейсы

- Обязательная зависимость — обычный параметр, не `variadic`. `NewPipeline(..., resultBuilder
  ...ResultBuilder)` превращает ошибку компиляции в четыре runtime-проверки.
- Логгер по умолчанию — `slog.New(slog.DiscardHandler)`, а не `nil` с проверками на каждом вызове.
- Интерфейс объявляется у потребителя и держится узким. `PipelineRepository` на 13 методов
  заставляет каждый тест реализовывать всё целиком.

## Размеры

Ориентиры, а не догма: функция — до ~60 строк, файл — до ~500. Линтер настроен на
`gocyclo 20` / `gocognit 30`. Сегодня за порогом 12 функций, включая `main()` (317 строк)
и `keysso.cleanDuplicates` (175).

## Навигация через gopls MCP

Подключён официальный MCP-сервер gopls. Он даёт ответы уровня компилятора там, где `grep`
даёт ложные совпадения по строкам и комментариям:

- `go_search` — найти символ по нечёткому имени.
- `go_file_context` — что этот файл использует из своего пакета. Вызывать сразу после
  первого чтения любого `.go`.
- `go_package_api` — публичный API пакета, без чтения его файлов целиком.
- `go_symbol_references` — **все** использования символа. Обязательно перед изменением
  сигнатуры или удалением: аудит нашёл ~1300 строк мёртвого кода, и отличить мёртвое от
  живого можно только так.
- `go_diagnostics` — ошибки сборки и анализа по изменённым файлам. Вызывать после каждой
  правки, до запуска тестов.
- `go_vulncheck` — при изменении `go.mod`.

Порядок редактирования: прочитать → `go_symbol_references` → правки → `go_diagnostics` →
исправить → тесты затронутых пакетов.

## Проверка перед сдачей

`make fmt && make vet && make lint && make test` — либо `/ship`, который делает это плюс
проверку, что тесты репозитория действительно выполнились, а не пропустились.
