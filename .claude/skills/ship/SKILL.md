# Ship

Проверить изменения перед коммитом. Шаги идут по возрастанию стоимости: дешёвые и быстрые
первыми, чтобы не ждать тесты ради ошибки форматирования.

Каждый шаг имеет **критерий прохождения**. Шаг не пройден — остановиться, починить,
начать с него заново. Не переходить дальше «в целом нормально».

## Шаг 1. Формат

```
gofmt -l .
```

**Пройден:** вывод пуст. Непустой — перечислены файлы, требующие `make fmt`.

## Шаг 2. Статический анализ

```
make vet
```

**Пройден:** код возврата 0.

## Шаг 3. Линтер

```
make lint
```

Ненулевой код возврата — норма: baseline проекта ровно **71 замечание**, они разбираются
по [бэклогу аудита](../../../docs/AUDIT-2026-08.md). `golangci-lint` v2 возвращает при
найденных замечаниях **2**, а `make` превращает это в `Error 1` в своём сообщении — не
путать одно с другим.

Счётчик текущих замечаний:

```
make lint 2>&1 | grep -c '\.go:'
```

**Пройден:** в изменённых файлах **нет новых** замечаний по сравнению с baseline. Сверять
по именам файлов из `git diff --name-only`, а не по общему счётчику: чужие замечания в
нетронутых файлах — не повод блокировать коммит, свои новые — повод.

## Шаг 4. Тесты

```
make test
```

**Пройден:** все пакеты `ok` или `no test files`.

## Шаг 5. Race detector по всем пакетам

```
go test -race ./...
```

Именно так, **не** `make test-race`: цель в Makefile покрывает только
`./internal/tasks/task1/...`, а конкурентность живёт в `internal/llm` (heartbeat-goroutine)
и `internal/llm/deepseekweb` (mutex + семафор). Это находка M13.

**Пройден:** код возврата 0, ни одного `WARNING: DATA RACE`.

## Шаг 6. Тесты репозитория действительно выполнились

Самый важный шаг гейта. Без `TEST_DATABASE_URL` все 15 тестов
`internal/tasks/task1/repository` **молча пропускаются**, а `make test` при этом зелёный —
покрытие слоя данных ноль (находка C3). Шаги 4 и 5 этого не замечают.

```
docker compose up -d --wait postgres-dry-run
TEST_DATABASE_URL='postgres://seo:seo@localhost:5433/seo_dry_run?sslmode=disable' \
  go test -count=1 -v ./internal/tasks/task1/repository/... 2>&1 | grep -c -- '--- SKIP'
```

**Пройден:** счётчик `--- SKIP` равен 0 и тесты завершились `ok`. Ориентир: 15 тестов,
покрытие ~63%. Контейнер после проверки остаётся поднятым — это нормально, гасить его
не нужно.

Ненулевой счётчик означает, что проверки транзакций, `RowsAffected` и инварианта
`FOR UPDATE SKIP LOCKED` ([ADR-0002](../../../docs/adr/0002-skip-locked.md)) не выполнялись —
результат гейта недействителен.

Контейнер не поднимается — сказать об этом прямо и не выдавать шаг за пройденный.

## Шаг 7. Синхронность связанных файлов

Проверить по `git diff --name-only`:

- изменены `migrations/**` → обязана быть правка `expectedSchema` в
  `internal/tasks/task1/repository/schema.go`, иначе приложение не стартует
  ([ADR-0003](../../../docs/adr/0003-validate-schema.md));
- изменён `config/config.yaml` → затронутые стадии остались в `requiredLLMStages`,
  у каждой непустой `targets`;
- добавлен доменный термин → он есть в [docs/CONTEXT.md](../../../docs/CONTEXT.md);
- изменено поведение, описанное в ADR → ADR обновлён или заведён новый.

**Пройден:** каждая связка либо соблюдена, либо явно названа как сознательно пропущенная.

## Шаг 8. Отчёт

Свести результат: что проверено, что прошло, что нет. Провалившиеся шаги называть с
фактическим выводом команды, а не пересказом.

Отдельно перечислить, что попадёт в коммит (`git status --short`), и убедиться, что там
нет чужой незавершённой работы — в этом дереве такое уже случалось.

Проверить, что в индексе нет файлов, которые числятся в `.gitignore`: для отслеживаемого
файла правило игнорирования не действует, поэтому он молча попадает в каждый `git add -A`.

```
git ls-files -z | xargs -0 git check-ignore --no-index 2>/dev/null
```

**Пройден:** вывод пуст. Непустой — перечисленные файлы нужно открепить
(`git rm --cached <file>`) отдельным решением, а не заодно с текущей работой.

## Коммит

Только при `--commit` в аргументах и только если все восемь шагов пройдены.

Сообщение — Conventional Commits, как в истории: `feat:`, `fix(task1):`, `refactor(task1):`,
`chore:`, `docs:`. Без co-author трейлеров (`includeCoAuthoredBy: false`).

Без `--commit` — остановиться на отчёте.
