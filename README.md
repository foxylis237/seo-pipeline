# SEO Pipeline

Go-приложение для поэтапной подготовки и генерации SEO-статей. Текущий
сценарий выделен как `task_1`. Его основной сценарий `run` — демонстрационный
MVP для проверки данных, промптов, общего LLM-контекста, публикационной
информации и итогового `result.md`.

## Расположение файлов task_1

```text
tasks/task_1/
  input/       входной Excel (`input.xlsx` по умолчанию)
  output/      сгенерированные артефакты
  prompts/     промпты этапов LLM
  templates/   шаблон итогового результата
```

Пути по умолчанию задаются централизованно в `internal/config`, а пути
LLM-промптов — в `config/config.yaml`. Вход и выход можно переопределить через
`INPUT_FILE_PATH` и `OUTPUT_DIR`.

Пользовательские промпты нельзя изменять без явного запроса пользователя.
При изменении формата ответа нужно адаптировать парсер и инфраструктуру.

Специфичный Go-код пайплайна находится в `internal/tasks/task1/`. Общими
остаются `internal/config`, `internal/llm`, `internal/storage` и интеграции.

## Настройка

Скопируйте `.env.example` в ожидаемый проектом `.env` и укажите PostgreSQL,
учётные данные интеграций, `GEMINI_API_KEY` и `GEMINI_MODEL`. Альтернативный
файл окружения можно выбрать переменной `ENV_FILE`.

Примените SQL-миграции из `migrations/` в порядке номеров.

## Команды task_1

Во всех командах `<external_id>` — положительный ID статьи из импортированного
Excel.

```bash
go run ./cmd/seo-pipeline task-1 import
go run ./cmd/seo-pipeline task-1 import path/to/input.xlsx
go run ./cmd/seo-pipeline task-1 prepare <external_id>
go run ./cmd/seo-pipeline task-1 run
go run ./cmd/seo-pipeline task-1 demo-generate <external_id>
```

`import` добавляет новые строки по уникальному `external_id`, пропускает уже
импортированные и логирует количество найденных, добавленных и пропущенных
строк. Импорт никогда не запускается командой `run`.

`run` последовательно запускает текущий демонстрационный MVP-пайплайн для всех
уже импортированных незавершённых статей:

1. Подготавливает сохранённые входные данные статьи.
2. Собирает необходимые промпты.
3. Демонстрационно генерирует текст статьи в общем LLM-контексте.
4. В том же контексте генерирует и парсит `info`.
5. Сохраняет состояние и файлы, затем формирует `result.md`.

Следующая статья выбирается по `status <> 'completed'` в порядке `id ASC`.
После успеха статья получает `completed`, и обработка переходит к следующей.
После первой ошибки `run` сохраняет ошибку существующим механизмом и
останавливается; следующий запуск снова начинает с первой незавершённой статьи.
Связанные ответы `article + info` считаются одним этапом и при ошибке повторяются
вместе.

`demo-generate <external_id>` — совместимый ручной запуск того же сценария для
одной статьи. Также для отладки поддерживается `run <external_id>`.

Текущая генерация статьи не считается финальной. `review`, `fix` и `html` не
входят в сценарий `run`. Основная задача этой версии — проверить подготовку
данных и промптов, общий контекст LLM, генерацию и парсинг `info`, сохранение
состояния и сборку итогового результата. Полноценная генерация и редактура
статьи будут добавлены позднее с использованием OpenAI или Claude.

Незавершённые этапы по-прежнему доступны как отдельные команды для разработки
и проверки:

```bash
go run ./cmd/seo-pipeline task-1 generate <external_id>
go run ./cmd/seo-pipeline task-1 review <external_id>
go run ./cmd/seo-pipeline task-1 fix <external_id>
go run ./cmd/seo-pipeline task-1 info <external_id>
go run ./cmd/seo-pipeline task-1 html <external_id>
```

`generate` пока сохраняет прежний полный экспериментальный flow после
`prepare`, но не является основным MVP-сценарием. Команда
`info` сохраняет прежнюю семантику связанного этапа: статья и информация для
публикации генерируются последовательно в одном чате, чтобы промпт `info` видел
написанную статью.

Дополнительные обслуживающие команды также находятся внутри группы задачи:

```bash
go run ./cmd/seo-pipeline task-1 article <external_id>
go run ./cmd/seo-pipeline task-1 result <external_id>
```

Имя `task_1` временно принимается как совместимый вариант группы; в новых
командах используйте `task-1`. Старые команды без группы задачи больше не
принимаются.

## Добавление task_2

Для независимого пайплайна добавьте `tasks/task_2/{input,output,prompts,templates}`
и новую ветку разбора группы `task-2` в CLI. Общие клиенты LLM, PostgreSQL,
конфигурацию, логирование и файловые утилиты оставляйте в `internal`; модели,
этапы и сервисы конкретного сценария размещайте в отдельном task-пакете только
когда появляется фактическая вторая реализация.
